# Falcon Render v0.1

Blender 5.2.0 LTS をベースにした、**コースティクス(光の集光)と下描きの速さ**に手を入れた
レンダリング特化ビルドです。Linux x86_64 / NVIDIA GPU 向け。

起動時のバージョン表示: `Falcon Render v1「Blender 5.2.0 LTS.C2 DLSS」`

---

## 何が本家と違うか

| 機能 | 内容 |
|---|---|
| **Falcon ライトトレース** | 光源側から光を飛ばし、通常の Cycles が苦手な集光(水面・ガラス・金属の反射光)を直接描く |
| **ワールドフォトン** | 環境光(HDRI)由来の集光にも同じ仕組みを使う |
| **SHARC キャッシュ** | 空間ハッシュに放射輝度を貯めて再利用する |
| **誤差場キャッシュ** | どのセルが収束したかを測り、済んだ経路の追跡をやめる。**下描きで約 20% 短縮** |
| **発射誘導** | 光子を撒く方向を実測で配分する。同じ予算でノイズ −9.6% |
| **LT 再合成** | 集光レイヤーの強さ・ぼかしの調整が **0.1 秒**(従来はレンダーやり直しで 197 秒) |
| **DLSS-RR** | NVIDIA のデノイザ。条件付き(後述)。アニメでのちらつきに強い |

## 導入

```bash
tar xf falcon-render-v0.1-linux-x86_64.tar.xz
cd falcon-render-v0.1-linux-x86_64
./falcon-render.sh
```

`falcon-render.sh` から起動してください。直接 `./blender` を叩いても動きますが、
起動スクリプトが以下の 2 つを設定しています。

- `OPTIX_CACHE_PATH` — これが無いと**初回レンダーで最大 20 分固まります**(OptiX が
  10MB の PTX を再コンパイルするため)。途中で強制終了するとキャッシュが残らず、毎回やり直しになります
- `__NGX_DISABLE_UPDATER=1` — DLSS の更新チェックがネットワーク待ちで止まるのを防ぎます

### 動作環境
- NVIDIA GPU(OptiX を使うので RTX 系推奨。開発は RTX 3080 で行っています)
- Linux x86_64

## DLSS について(重要)

**DLSS-RR は「動く環境なら動く」オプション扱いです。既定では使えません。**

Linux の DLSS はドライバが署名済みのライブラリしか読み込まない仕組みになっていて、
NVIDIA はこのファイルを一般には配っていません。本ビルドは**署名済みライブラリを同梱していません**。
手元に正規に入手した `libnvidia-ngx-dlssd.so` がある場合のみ、展開先の直下に置けば
デノイザの選択肢に DLSS が出ます。

なお **Blender 5.3(2026 年秋予定)で DLSS 4.5 RR が公式統合される見込み**です
(NVIDIA から本家へパッチが出ています)。そちらが入れば、この手間は要らなくなります。

また v0.1 では安全ガードとして、**DLSS デノイズを使った最終レンダーは 1920x1080 まで**に
制限しています(それを超えるとエラーで停止します)。4K などの高解像度でフレームがタイル分割される
経路の検証が済んでいないためで、事故で壊れた絵を出すより止める方を選んでいます。
ビューポートには制限はありません。検証が済み次第このガードは外します。

**DLSS が無くても、上の表の他の機能はすべて動きます。** Falcon Render の中身は
コースティクスと下描きの速さで、DLSS はおまけです。
