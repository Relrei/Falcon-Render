# Falcon Render v0.4.1

*[English version / 英語版はこちら](README.en.md)*

Blender 5.2.1 LTS ベースの改造ビルド。コースティクス(集光)計算とプレビューレンダーの
速度、動画編集(VSE・v0.4)に加え、**v0.4.1 では DLSS Ray Reconstruction によるアニメーションのレンダリング**を実用の形にしている。
対象環境: Linux x86_64 / NVIDIA GPU。

起動時バージョン表示: `Falcon Render v0.4.1`

---

## この版について(デモ版・無料)

**v0.4.1 は無料で配布するデモ版です。機能の制限はありません。**
このパッケージで、下の「標準版との差分」に挙げた機能はすべて使えます。

**名乗りの読み方(2026-09-01 に整理しました)**

- **`Falcon Render v0.4.1`** = いま手元にあるこのパッケージ。**配布向けに切り出して調整したもの**
- **`Falcon Render`**(版を名乗らない) = 開発者の手元でリアルタイムに進んでいる最新。配布はしていません

つまり**版数が付いていれば配布物**です。同梱の `FALCON_FLAVOR` に、
そのビルドの種別(`release`)と、入っている GPU 実験機能の一覧が書いてあります。
**配布物ではこの一覧が必ず空**です。

GPU 化を進めている途中の機能(スカルプトのブラシを GPU で回す・スカルプト表示の溶接・
order engine の専用モード)は、**ビルド自体に含まれません**(環境変数を置いても動きません)。
作り方の順序は **個人運用 → 切り離しビルド → 販売** で、
**GPU 処理は販売版の機能**です。

以降の版は有料での配布を予定しています。**旧版が無料・最新版が有料**という形で、
Blender と同じ GPL で配布されるため、**受け取った版のソースは常に付いてきます**。

## v0.4.1 の変更点

**この版の主題は DLSS-RR(Ray Reconstruction)によるアニメーションのレンダリングです。**詳細と実測値は
[RELEASE_NOTES_v0.4.1.md](RELEASE_NOTES_v0.4.1.md) を参照してください。

| | 内容 | 効き |
|---|---|---|
| **カメラ切り替え直後のざらつき** | カットの検出が最終レンダーで一度も効いていなかったのを直した | 残差 隣の 1.88 倍 → **0.96 倍**・費用 0 秒 |
| **連番の費用** | NGX の初期化はジョブに1回だけ | 1391 コマ **83.6 分**(1コマ中央値 3.51 秒) |
| **煙・VDB のコマ** | 境界メッシュの再構築(毎コマ NanoVDB→OpenVDB)を消した | res160 **−18〜29%** |
| **常駐データ** | Persistent Data を既定 ON | — |
| **VSE の書き出し** | fast path / GPU 符号化のどれが効いたかを出力プロパティに1行 | — |
| **起動と UI(Linux)** | Hyprland / Sway では XWayland で起動(クリックが効かなくなる閂・320x240 のファイルブラウザの回避)。初回起動だけ 解像度スケール 1.25・ファイルブラウザ=最大化エリア を既定に | 戻す口 `FALCON_FORCE_X11=0` / プリファレンスで変更 |

> DLSS のバイナリは同梱していません(v0.4 と同じ)。NVIDIA から正規に入手した `libnvidia-ngx-dlssd.so` を
> 展開先の直下に置くと有効になります(下の「DLSSについて」)。
> **1枚の正確さは OIDN のほうが良い**(実測・RELEASE_NOTES 参照)。DLSS-RR を選ぶのは 4K ビューポートの速さと連番の安定のためです。

## v0.4 の変更点

**この版の主題は動画編集(VSE)です。**詳細と実測値は
[RELEASE_NOTES_v0.4.md](RELEASE_NOTES_v0.4.md) を参照してください。

| | 内容 | 効き |
|---|---|---|

| **色補正** | 自動ベクトル化が効く形へ書き直し | **3.8 倍**(画素は従来と完全一致) |
| **プレビュー** | モディファイアをプレビュー解像度で掛ける | 25% 表示で **13 倍** |
| **動画の書き出し** | GPU エンコード(NVENC)を既定で使う。開けなければ自動で CPU へ | — |
| **メモリ** | 機械の空きが尽きかけたらキャッシュを手放す | ピーク **2450 → 1443MB** |
| **連番の保存** | 保存をレンダーに重ねる | EXR **230 → 42ms** |

レンダリング側:

- **土台を Blender 5.2.1 LTS へ**(v0.3 は 5.2.0 LTS)
- **レンダー領域でカメラカリングを絞る**(従来は領域を無視して画面全体と比べていた)。
  ⚠ 領域の外に光源があると照明ごと消えます。既定の余白では変わりません
- **Vulkan: GPU メモリ不足で落ちない**
- 最終レンダー中はビューポート側の GPU メモリを退避(既定 ON)

### v0.3 の変更点

修正が中心のアップデートです。**v0.2 で GPU レンダーが使えなかった不具合を含みます。**

#### ★配布物で GPU レンダーが使えなかった不具合を修正

v0.2 の配布物には GPU カーネルの組み立てに必要なヘッダが 2 つ入っていませんでした。
GPU のカーネルは実行時にソースを読んでコンパイルするため、**ビルドも CPU レンダーも
通り、GPU レンダーだけが失敗します**。v0.2 を GPU で使えなかった方は、こちらが原因です。

再発を止めるため、配布したソースだけでカーネルが閉じているかを確かめる検査を
パッケージ作成の手順に組み込みました。

#### 他人の `.blend` を開いたときの 3 件を塞いだ

`.blend` に書かれた本ビルド固有の設定値が、読み込み時に検証されずそのまま使われていました。

| | v0.2 | v0.3 |
|---|---|---|
| 任意のファイルが 1 GiB で上書きされる | 踏める | 塞いだ(キャッシュは `~/.cache/falcon_photon/` へ読み替え) |
| 確保より大きく読む | 踏める | 撥ねて完走 |
| 異常な半径で戻ってこなくなる | 素通り | 8.0 に切り詰め |

**正常系は変えていません**: 同じシーンのコースティクス出力がバイト単位で一致
(差はヘッダの日時のみ)、速度は 0.963〜1.021 倍。
他人のファイルを開く前に、実行される面と本ビルド固有の値を一覧で見る検査器も入れました。

#### リメッシュに「目標の面数」

- 面数を直接指定できるようにしました(投影面積から 1 回で当てます)
- adaptivity と併用したときは、繰り返して目標に寄せます
- スカルプトのマスクを尊重します
- **UV と頂点カラーが落ちていたのを直しました**
- 目標が大きすぎる場合は、警告ではなく走らせません(戻ってこなくなるため)

#### スカルプト表示の高速化(溶接)— この版には入っていません

同じ位置の頂点をまとめてから GPU へ送る仕組みです。手元の計測では効果が出ています
(400 万面で位置バッファの作り直し 6.90 ms → 1.59 ms・1 回に送る量 30.4 MB → 8.0 MB・
表示全体は 200 万面で 51.2 ms → 42.6 ms)。

ただし Blender 5.3 でスカルプト表示の作りが変わる予定と重なるため、**この release 版には
ビルドに含めていません**。開発者の `Falcon Render debug` 版でのみ有効です。

#### コースティクスの修正

- 太陽を「円盤」として撃つようにしました(点光源の太陽を焼いていた)
- 点光源・面光源(楕円・スプレッド)・スポット(半径・縁の減衰)がそれぞれ正しい形で光子を撃つようになりました
- 格子が衝突したときに出ていた白い点を直しました
- 光子の予算を、ワット数ではなく「実際に届く割合」で灯へ配るようにしました
- 既定の光子数を 2000 万 → 10 億にしました(CPU 時代の値が残っていました)
- ライトトレース合成が、焼いた光子キャッシュを 1 GB のゼロで潰していたのを直しました
- ライトトレースがシーンのコンポジター出力を二重に数えていたのを直しました
- ライトトレースが受光面の裏側にも全額を足していたのを止めました
- **ライトトレースが、光源に大きさを与えると画面全体を一律に明るくしていたのを直しました**

#### 表示名

起動時の表示を `Falcon Render v0.3` にしました。開発者向けの debug 版は
`Falcon Render debug` と表示されるので、どちらのビルドか一目で分かります。

</details>

## 標準版との差分

| 機能 | 内容 |
|---|---|
| 蓄積グリッド コースティクス | 光子を固定サイズの格子に足し込む。撃つ数によらず描画時間は一定 |
| Falcon ライトトレース | 光源側からレイを追跡し、水面・ガラス・金属反射などの集光を直接計算する |
| ワールドフォトン | 環境光(HDRI)由来の集光にも同じ手法を適用する |
| SHARC キャッシュ | 空間ハッシュに放射輝度を保存し再利用する |
| 誤差場キャッシュ | セルごとの収束状態を判定し、収束済み経路の追跡を打ち切る。プレビューレンダー時間を約20%短縮 |
| 発射誘導 | 光子の射出方向を実測データに基づき配分する。同一サンプル数でノイズを9.6%低減 |
| LT 再合成 | 集光レイヤーの強度・ぼかしを0.1秒で再調整可能(従来はレンダー再実行が必要、197秒) |
| DLSS-RR | NVIDIA製デノイザー。利用には条件あり(下記)。アニメーションのちらつきを抑制 |
| リメッシュの目標面数 | 面数を直接指定してボクセルリメッシュをかける。adaptivity と併用可 |
| **VSE fast path** | 切っただけの書き出しを再符号化せずに通す。FHD 6.8 倍 / WQHD 9.5 倍 |
| **VSE 先読みデコード** | 再生 5.6 倍(52.2ms → 9.40ms/コマ) |
| **VSE 色補正の高速化** | 3.8 倍。出力画素は従来と完全一致 |
| **VSE プレビュー縮小** | モディファイアをプレビュー解像度で掛ける。25% で 13 倍 |
| **GPU 動画エンコード** | NVENC。開けない組み合わせは自動で CPU へ降りる |
| **VSE メモリ圧力の解放** | 空きが尽きかけたらキャッシュを手放す。ピーク 2450 → 1443MB |
| **保存とレンダーの重ね** | 連番書き出しで保存待ちを隠す。EXR 230 → 42ms |
| **レンダー領域カリング** | カメラカリングをレンダー領域に従わせる |

## 導入手順

```bash
tar xf falcon-render-v0.4.1-linux-x86_64.tar.xz
cd falcon-render-v0.4.1-linux-x86_64
./falcon-render.sh
```

`falcon-render.sh` から起動すること。`./blender` を直接実行しても動作するが、
起動スクリプトは以下2点を設定する。

- `OPTIX_CACHE_PATH`: 未設定の場合、初回レンダー時にOptiXが10MBのPTXを再コンパイルし、
  最大20分停止する。処理中に強制終了するとキャッシュが保存されず、再度同じ待機が発生する
- `__NGX_DISABLE_UPDATER=1`: DLSSの更新チェックによるネットワーク待機を無効化する
- Hyprland / Sway / river(wlroots 系)では **XWayland で起動する**(v0.4.1)。Wayland 直だと OS キーが押しっぱなしに閂されて
  クリックが効かなくなる(Blender #161108)/ ファイルブラウザが 320x240 で出る(#162315)ため。
  常に Wayland で起動したい時は `FALCON_FORCE_X11=0 ./falcon-render.sh`、他のデスクトップで XWayland にしたい時は `FALCON_FORCE_X11=1`

### 動作環境

- NVIDIA GPU(OptiX使用のためRTXシリーズ推奨。開発環境はRTX 3080)
- Linux x86_64

## DLSSについて

DLSS-RR は動作環境が揃った場合のみ使えるオプション機能で、**既定では無効**です。
DLSS を使わなくても他の機能はすべて動作します。

**本パッケージには DLSS のランタイムライブラリを同梱していません**(v0.1 以降すべて同じです)。
配布物に NVIDIA のコードは1バイトも入っていません(固める直前に現物を数えて確かめています)。
Linux 版の DLSS はドライバが署名済みライブラリのみを読み込む仕様のため、正規に入手した
`libnvidia-ngx-dlssd.so` を展開先の直下に置いた場合にだけ、デノイザーの選択肢に DLSS が出ます。

> 同梱については、NVIDIA RTX SDKs License がオブジェクトコードでの再配布を許可している一方で、
> 事前通知(§3)と、スプラッシュ/アバウトボックスへの NVIDIA 商標の表示(§6.1(b)・
> 表示サンプルの2週間前の提出と事前承認が必要・§6.2(c))を求めています。
> **この2つが済むまでは同梱しません。**

**Blender 5.3(2026-11-10 予定)で DLSS RR が公式統合される見込みです。**
統合後はこの手順そのものが不要になります。
(2026-08-12 時点の 5.3.0 Alpha にはまだ入っておらず、デノイザーの選択肢は
OptiX と OpenImageDenoise のみでした)

v0.1 にあった「DLSS 最終レンダーは 1920x1080 まで」の制限は **v0.2 で撤廃**しました。
当時は高解像度でタイル分割された時の経路が未検証で、かつ制限に引っかかった場合に
異常終了する不具合があったため、安全側に倒していました。v0.2 では異常終了を修正し、
判定を解像度ではなくタイル分割の有無に変更しています(壊れるのは解像度そのものでは
なくタイル分割時だったためです)。

2026-08-12 に確認した範囲では、2560x1440 も、タイル分割を強制した 1920x1080 も
正常に完走しています。ただし**4K以上での長時間レンダーはまだ十分に踏んでいません**。
問題が出た場合は `FALCON_DLSS_ALLOW_HIGHRES=0` ではなく、報告してもらえると助かります。
