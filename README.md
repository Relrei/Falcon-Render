# Falcon Render v0.2

Blender 5.2.0 LTS ベースのレンダリング特化ビルド。コースティクス(集光)計算と
プレビューレンダーの速度に変更を加えている。対象環境: Linux x86_64 / NVIDIA GPU。

起動時バージョン表示: `Falcon Render v1「Blender 5.2.0 LTS.C2 DLSS」`
(内部の表示名は v1 のまま。配布パッケージの版数とは別です)

---

## v0.2 の変更点

修正が中心のアップデートです。

**コースティクスの計算方式を蓄積グリッドに変更**

光子を1個ずつ保存して描画時に探す方式から、固定サイズのハッシュに足し込む方式へ
移行しました。**光子を何個撃っても描画時間が変わらず**、伸びるのは焼く時間だけです。
ガラス 12 体のシーンで描画 **122 秒 → 3.8 秒**。GUI の「コースティクスを焼く」だけで
動き、環境変数の設定は要りません。合わせて格子の衝突(粒の原因)と、法線の向きに
よって結果が変わる問題を直しています。

**DLSS の連番レンダー**

- 指定サンプル数を大幅に超過して消費し続ける不具合を修正(詳細は KNOWN_ISSUES.md)
- 「初回蓄積レンダリング回数」を設定項目として追加。従来は環境変数だけで、
  UI から触れませんでした
- **最終レンダーの 1920x1080 制限を撤廃**(下記)

## 標準版との差分

| 機能 | 内容 |
|---|---|
| 蓄積グリッド コースティクス | 光子を固定サイズの格子に足し込む。撃つ数によらず描画時間は一定 |
| Falcon ライトトレース | 光源側からレイを追跡し、水面・ガラス・金属反射などの集光を直接計算する |
| ワールドフォトン | 環境光(HDRI)由来の集光にも同じ手法を適用する |
| SHARC キャッシュ | 空間ハッシュに放射輝度を保存し再利用する |
| 誤差場キャッシュ | セルごとの収束状態を判定し、収束済み経路の追跡を打ち切る。プレビューレンダー時間を約20%短縮 |
| 発射誘導 | 光子の射出方向を実測データに基づき配分する。同一サンプル数でノイズを9.6%低減 |
| LT 再合成 | 集光レイヤーの強度・ぼかしを0.1秒で再調整可能(従来はレンダー再実行が必要、197秒) |
| DLSS-RR | NVIDIA製デノイザー。利用には条件あり(下記)。アニメーションのちらつきを抑制 |

## 導入手順

```bash
tar xf falcon-render-v0.2-linux-x86_64.tar.xz
cd falcon-render-v0.2-linux-x86_64
./falcon-render.sh
```

`falcon-render.sh` から起動すること。`./blender` を直接実行しても動作するが、
起動スクリプトは以下2点を設定する。

- `OPTIX_CACHE_PATH`: 未設定の場合、初回レンダー時にOptiXが10MBのPTXを再コンパイルし、
  最大20分停止する。処理中に強制終了するとキャッシュが保存されず、再度同じ待機が発生する
- `__NGX_DISABLE_UPDATER=1`: DLSSの更新チェックによるネットワーク待機を無効化する

### 動作環境

- NVIDIA GPU(OptiX使用のためRTXシリーズ推奨。開発環境はRTX 3080)
- Linux x86_64

## DLSSについて

DLSS-RRは動作環境が揃った場合のみ利用可能なオプション機能であり、既定では無効。

Linux版DLSSはドライバが署名済みライブラリのみを読み込む仕様であり、NVIDIAはこの
ライブラリを一般公開していない。本ビルドには署名済みライブラリを同梱していない。
正規に入手した`libnvidia-ngx-dlssd.so`を展開先直下に配置した場合のみ、デノイザーの
選択肢にDLSSが表示される。

Blender 5.3(2026年秋予定)でDLSS 4.5 RRが公式統合される見込みがある(NVIDIAから
本家へのパッチが提出済み)。統合後はこの手順は不要になる。

**ただし 2026-08-12 時点の 5.3.0 Alpha(`main.8eb257c2b2df`)には、まだ入っていない。**
デノイザーの選択肢は OptiX と OpenImageDenoise のみで、NGX 関連のライブラリも
同梱されていないことを確認した(バイナリ内の "DLSS" を含む文字列3件は、いずれも
iTaSC ソルバの型名と GLSL の定数で、DLSSとは無関係)。統合の時期は未定と見ている。

v0.1にあった「DLSS最終レンダーは1920x1080まで」の制限は**v0.2で撤廃**した。当時は
高解像度でタイル分割された時の経路が未検証で、かつ制限に引っかかった場合に
異常終了する不具合があったため、安全側に倒していた。v0.2では異常終了を修正し、
判定を解像度ではなくタイル分割の有無に変更している(壊れるのは解像度そのものでは
なくタイル分割時だったため)。

2026-08-12 に確認した範囲では、2560x1440 も、タイル分割を強制した 1920x1080 も
正常に完走している。ただし**4K以上での長時間レンダーはまだ十分に踏んでいない**。
問題が出た場合は `FALCON_DLSS_ALLOW_HIGHRES=0` ではなく、報告してもらえると助かる。

DLSSが無効でも上記の他機能は全て動作する。DLSSはオプション機能であり、コースティクス
計算とプレビューレンダー速度がこのビルドの中心機能である。
